Hash quality

Naddu's Zobrist hash is two 32 bit halves. Eight workers play random games and report the hash of every position with the hash command, then the page checks the keys the way a hash table cares about them:

  • Collisions. Two different positions with the same 64 bits. With a sound key this is a once in a lifetime event; with a 32 bit key in disguise it happens every few hundred thousand positions.
  • Linearity. Zobrist keys are combined by exclusive or, which is addition over GF(2), so if the second half of every key is a linear function of the first, the second half of every position's hash is too and it verifies nothing. The page fits such a function from a few positions by Gaussian elimination over GF(2) and tries it on all the rest, both ways round.
  • Bit balance. Each of the 64 bits should be set in half the positions.
  • Slot spread. The low bits pick the hash table slot, so the positions should spread evenly over them.
